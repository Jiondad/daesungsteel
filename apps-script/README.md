# Apps Script 서버 v2 설치 안내

기존(v1)은 **전체 데이터를 A1 셀 하나에 JSON 문자열로 통째로** 넣었습니다. v2는 시트를 표로 나눠 저장합니다.

| 시트 | 내용 |
|---|---|
| Records | 월별 실적(연·월·경유·도시가스·전력·수도·매출) + **수정 시각·수정자** |
| Targets | 월별 목표 + 수정 시각·수정자 |
| PlanMeta | 목표 수립 기록(방법·기준 연도·목표 출처·사유) |
| Config | 연도 목록, 보고서 설정(조직경계·계수 출처·결재자) |
| Scenarios | 로드맵 시나리오(가정·근거·결과) |
| ClosedMonths | 월 마감 현황(마감 시각·마감자·사유) |
| **AuditLog** | **변경 이력(추가만 함)** — 시각·버전·작업자·작업·변경 전→후 값 |
| Backup | 저장 직전 데이터의 스냅샷(최근 30개) |
| Meta | 데이터 버전 |

이 시트들은 서버가 자동으로 만듭니다. 값을 시트에서 직접 고치지 마세요(변경 이력이 남지 않고 버전이 어긋납니다).

## 설치 순서 (반드시 이 순서로)

> 새 화면(GitHub)을 먼저 배포하면 관리자 로그인이 서버와 맞지 않아 저장이 안 됩니다. **서버 → 화면** 순서로 진행하세요.

### 1단계. 코드 교체
1. 데이터가 들어 있는 구글 시트 → **확장 프로그램 → Apps Script**
2. 기존 `Code.gs` 내용을 모두 지우고, 이 폴더의 `Code.gs` 내용으로 교체 → 저장
3. **(권장) 시트 사본 만들기**: 파일 → 사본 만들기. 기존 데이터는 A1 셀에 그대로 남으므로 지워지지 않지만 안전을 위해 사본을 만들어 두세요.

### 2단계. 관리자 계정 만들기 (택 1)
**A. 이름별 계정(권장 — 누가 저장했는지 이력에 이름이 남음)**
1. 편집기 왼쪽 위 함수 목록에서 `setupAdminUser` 가 없으면, 코드 맨 아래에 아래 함수를 추가:
   ```javascript
   function setupAdminUser() { setAdminUser('홍길동', '여기에-8자-이상-비밀번호'); }
   ```
2. 이름과 비밀번호를 바꾼 뒤 `setupAdminUser` 를 선택하고 **실행**(최초 1회 권한 승인 필요)
3. **실행 후 위 함수의 비밀번호를 지우고 저장**합니다. 비밀번호 원문은 저장되지 않고 해시만 보관됩니다.
4. 사람마다 이름·비밀번호를 바꿔 반복 실행

**B. 공용 비밀번호(간단)**: 프로젝트 설정(톱니바퀴) → 스크립트 속성 → `ADMIN_PASSWORD` = 비밀번호. (이력에는 "관리자"로 남음)

### 3단계. 새 버전 배포
1. 오른쪽 위 **배포 → 배포 관리 → (기존 웹 앱 배포의) 연필 아이콘 → 버전: 새 버전 → 배포**
   - **기존 배포를 수정해야 URL이 그대로 유지됩니다.** "새 배포"를 만들면 주소가 바뀝니다.
2. 이 시점에는 `ENFORCE_AUTH` 가 없으므로 **호환 모드**입니다. 예전 화면도 계속 저장되지만 작업자는 "(인증 없음-호환 모드)"로 남습니다.

### 4단계. 새 화면 배포
GitHub에 새 소스를 올립니다(Actions가 초록색이 되면 완료). 화면 상단에 파란 안내가 보이면 **[표 구조로 이관]** 을 눌러(관리자 로그인) 한 번 저장하세요. 기존 A1 데이터가 표로 옮겨지고, 이관 전 원본은 Backup 시트에 따로 보관됩니다(A1 원본도 그대로 남습니다).

### 5단계. 인증 강제 켜기
새 화면이 정상 동작하는 것을 확인한 뒤: 프로젝트 설정 → 스크립트 속성 → `ENFORCE_AUTH` = `true` → **다시 새 버전으로 배포하지 않아도 즉시 적용**됩니다.
이후에는 로그인하지 않은 요청의 저장이 모두 거부됩니다.

## 동작 규칙
- **저장은 관리자 로그인 필요**(5단계 이후). 로그인은 6시간 유지되고, 10분 안에 10번 틀리면 잠깁니다.
- **동시 저장 방지**: 화면이 불러온 데이터 버전과 서버 버전이 다르면 저장을 거부하고 최신 데이터를 다시 불러옵니다.
- **월 마감**: 마감한 월의 실적은 수정·삭제할 수 없고, 해제하려면 사유가 필요하며 AuditLog에 남습니다.
- **입력 검증**: 음수·숫자가 아닌 값·13월·같은 월 중복 등은 서버가 거부합니다.
- **백업·복원**: 저장할 때마다 직전 데이터가 Backup 시트에 쌓입니다(최근 30개). 편집기에서 `restoreBackup(버전번호)` 를 실행하면 해당 버전으로 되돌립니다(복원도 이력에 남음).
- **읽기(조회)는 현재 로그인 없이 가능**합니다(대시보드는 공개 주소에서 누구나 볼 수 있는 상태와 동일). 조회도 제한하려면 별도 작업이 필요합니다.

## 한계
- 비밀번호는 서버에서 확인하지만, 웹 주소(GitHub Pages)와 Apps Script 주소가 공개되어 있어 **조회**는 막지 못합니다.
- 시트 편집 권한이 있는 사람은 시트를 직접 고칠 수 있습니다. 시트 공유 범위를 최소한으로 하고, 직접 수정은 하지 마세요(화면과 서버 버전이 어긋나고 이력에 남지 않습니다).

## 문제 해결: "인증 실패"가 나올 때

화면이 원인별로 안내 문구를 보여줍니다. 문구에 따라 아래를 확인하세요.

| 화면 문구 | 원인 | 조치 |
|---|---|---|
| 서버(Apps Script)가 새 버전(v2)으로 배포되지 않은 것 같습니다 | 코드를 **저장만** 하고 **배포**를 안 함(가장 흔함) | 배포 → 배포 관리 → 연필 아이콘 → 버전: **새 버전** → 배포 |
| 서버에 관리자 계정이 아직 설정되지 않았습니다 | 2단계(계정 만들기)를 아직 안 함 | 스크립트 속성에 `ADMIN_PASSWORD` 추가(또는 `setAdminUser` 실행) |
| 비밀번호가 올바르지 않습니다 | 비밀번호 불일치 | 한/영 전환·Caps Lock 확인. 속성값을 다시 붙여넣어 확인 |
| 로그인 시도가 너무 많습니다 | 10분 안에 10번 이상 틀림 | 10분 뒤 다시 시도 |

**서버 버전 직접 확인**: 웹 앱 주소(`.../exec`)를 브라우저 주소창에 붙여넣어 열었을 때
`대성스틸 온실가스 인벤토리 API v2.0 가동 중` 이 보이면 새 버전이 적용된 것입니다. `대성스틸 API 가동 중`만 보이면 아직 예전 코드입니다.

**스크립트 속성 위치**: Apps Script 편집기 왼쪽 톱니바퀴(프로젝트 설정) → 아래쪽 **스크립트 속성** → 속성 추가. (사용자 속성이 아니라 *스크립트* 속성입니다.)
